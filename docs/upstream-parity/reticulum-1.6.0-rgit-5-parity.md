## Caveats and Deferred Validation

- rns-rs TCP clients, Backbone clients and outbound I2P peers now synthesize
  tunnels, and rns-rs servers accept them (`1df27919`). This is new live
  behavior towards every peer of the deployed VPS nodes. A Python TCP client
  connecting to a Rust server is not exercised by the interop suite; only the
  Rust client to Python server direction is.
- rns-rs decides ingress holding before announce signature validation, and
  upstream validates first. During a burst, a blackholed or stamp-failing
  announce is held rather than counted as a filtered announce, and it is
  filtered when released.
- Tearing down an outbound I2P peer closes its stream, but its connection
  loop reconnects; upstream's detached peer stays down.
- Without interface management (no config file), a static configured
  interface cannot be detached, so a bad tunnel synthesis on one is only
  logged.
- `Transport.filtered_arxc` is not reported upstream and has no rns-rs
  equivalent.
- A non-transport node's transport identity stays ephemeral unless
  `static_transport_identity` is set, as upstream, so its tunnel id changes
  across restarts.
- Both VPS nodes still run their current builds; deployment is a separate
  operator step.
